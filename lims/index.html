01 现状

实验室里最难回答的，
往往是几个小问题。

它们不难在技术，难在信息散落在表格、聊天记录和某个人的记忆里。

01 / 样品

这支样品现在在哪？

领样、还样、销样、留样记在不同人的表格里，月底盘点只能靠回忆。

02 / 报告

这份报告是哪一版？

文件在群里传来传去，最终版永远躺在某个人的下载文件夹里。

03 / 进度

这个测试到哪一步了？

进度靠问，问不到就翻聊天记录，客户催的时候没人答得上来。

04 / 责任

这个操作是谁做的？

审核人、批准人、确认人写在纸上，真要追溯时对不上号。

这些问题不需要更努力地记录，只需要换一个地方记录。

02 业务链路

五个环节，一条链路。

上一步的数据就是下一步的输入。没有重复录入，也没有只存在某个人电脑里的中间版本。

受理组登记审核

一张单，装下送检信息和样品清单

受理组录入受理编号、送检单位、项目状态和保存条件，样品逐支登记，附件随单上传。提交后进入登记审核，审核人、时间与备注一并留在这张单上。

受理编号是后续所有动作的入口，全局唯一，不靠口头编号。

  • 受理编号全局唯一，可按编号、送检单位、项目状态检索
  • 一张受理单可登记多支样品，每支独立编号、独立流转
  • 登记审核记录审核人、审核时间与审核备注
  • Excel、PDF、Word、图片等附件随单保存，在线预览
技术组项目负责人

把一张单，拆成可执行的试验

技术组按样品拆出试验，每个试验有自己的编号、测试项目、测试方法、项目负责人和预计出报告时间。批量指派时，多行任务可以一次填完。

系统校验：送检单未审核通过，不能指派项目负责人。一条硬约束，胜过十条口头规定。

  • 试验编号全局唯一，一条任务对应一支样品
  • 测试方法支持标准、实验室、委托、非标准等类型
  • 预计出报告时间进入首页预警，提前 3 天提醒
  • 支持按送检单批量展开，多支样品一次指派
技术组样品管理员

样品在谁手里，状态说了算

技术员领样后在系统里登记，样品管理员确认；检测过程中维护样品状态与用样数量，完成后填写结论、实际起止时间与确认信息。

领样与处理都有操作人、确认人和时间，不靠「我记得给过他了」。

  • 样品状态：待检 → 在检 → 检毕，随实验推进更新
  • 领样数量、处理方式、处理数量逐条登记
  • 批量处理支持一次更新多条任务的实验信息
  • 确认人、确认日期、结论简述与试验备注完整留档
报告组多版本留痕

数据与报告，各有各的位置

上传原始数据与报告文件，填写报告编号、编写人和编写日期。同一个任务可以建多条数据处理记录，旧记录不覆盖，新版本从头走后续流程。

版本本身不是问题，「哪个才是最终版」才是。

  • 支持 Excel、CSV、Word、PDF、图片，单文件 ≤ 50MB
  • PDF、Word、Excel 附件浏览器内直接预览，不用下载
  • 报告编号回填到流程查询的「检测报告」页签
  • 同一任务可建多条记录，历史版本全部保留
报告组授权签字人

编制、审核、批准，三步都有名字

审核人确认后进入待批准，批准人批准即完成；同时登记报告正式上传日期与领取方式。状态由人员签字自动推导，不需要手工改。

待审核 → 已审核 → 已批准，每一步都能追到具体的人和时间。

  • 审核人与批准人分别记录，状态自动流转
  • 报告正式上传日期、领取方式（自取 / 寄送 / 其他）
  • 审核、批准均可填写备注，异常情况有地方说明
  • 报告列表支持按状态、报告编号、审核人与日期筛选

03 界面

不是流程图，
是每天打开的工作台。

三个最常用的界面：首页看板、流程查询、报告审核。它们读的是同一条链路。

界面示意，数据为示例；实际字段与布局以交付版本为准。

04 追溯

两条并行的证据链。

样品链回答「东西去哪了」，报告链回答「结论从哪来」。两条链在试验编号上对齐。

样品链

东西去哪了

  1. 受理登记
  2. 领样确认
  3. 在检
  4. 检毕
  5. 还样 / 销样 / 留样
  6. 到期处理

对齐键：样品编号 + 试验编号

报告链

结论从哪来

  1. 原始数据
  2. 报告编制
  3. 审核
  4. 批准
  5. 报告交付

任何一份报告，都能回到它用的那支样品；任何一支样品，都能回到它的受理单。

一条追溯路径
SUB-2026-0812受理单 → S-028样品 → SPF-2026-0312试验 → R-2026-1024报告

07 AI 接入

任何 AI，都能成为实验室的第二个入口。

基于标准 MCP 协议，腾讯 WorkBuddy、Codex、DeepSeek 等 AI 助手，都能接入同一个 LIMS：查数据、看进度，或在授权范围内写记录。权限照旧，全程留痕。

  • 15个
    只读查询

    受理、任务、样品、数据处理与报告审核记录，按编号与条件检索

  • 5个
    受控写入

    在授权范围内创建任务、更新实验与处理信息，沿用执行用户的业务权限

  • 1条
    审计链路

    每次调用记录客户端、执行用户、目标对象、结果与耗时

每个客户端独立 API Key，可单独开关写权限或停用；同一份数据，对所有接入的 AI 一致。

09 常见问题

上线前，六个常见问题。

答案都来自系统当前的实际能力，不做过期承诺。演示时可以逐条展开。

01 上线要停掉现有流程吗？
不用。可以先用一条业务线并行跑：新单走系统，旧单留在原处，跑顺之后再切换。受理编号与试验编号仍按你们现有的规则编，不需要推倒重来。
02 部署在实验室本地，还是云上？
两种都可以：装进实验室自己的服务器，或托管到云主机，浏览器打开就用。系统和数据分开存放，升级时不动业务数据。
03 权限能管到多细？
四个角色按模块授权，页面、按钮、字段三层控制。字段显示模板按人分配：同一张表单，给受理组和技术组套不同模板，看到的字段就不同。
04 报告改版了，旧版本怎么办？
新建一条数据处理记录，旧记录不覆盖；新报告重新走审核与批准。流程查询里能看到同一任务的多条数据处理与报告记录，审核人、批准人和时间各自独立。
05 现有的 Excel 台账能接进来吗？
样品入库支持工作簿批量导入，逐行校验；列表可以按自选字段导出。历史数据的迁移范围，建议在实施前按现有表格评估，先迁正在跑的单子。
06 AI 接入会不会绕过权限？
不会。任意支持 MCP 的 AI 助手（如腾讯 WorkBuddy、Codex、DeepSeek）都有独立 API Key，可只读或开放写入；每次调用绑定执行用户，沿用其业务权限并写入审计记录，写权限可随时关闭。
